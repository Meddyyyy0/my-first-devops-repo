# Практическая работа 4
Шведов Андрей Александрович, БСБО-13-25. Проверка 10 ноября 2026.

Mattermost 9.5.0 / MySQL 8.0 перенесён на Mattermost 12.0.1 / PostgreSQL 15.
Сохранены исходная учётная запись, приватный канал, пять контрольных сообщений, вложение и аватар. ID и тексты сообщений совпадают, вложение совпадает побайтово, SHA-256 аватара совпадает.

Два последовательных запуска GitHub Actions завершились успешно:
https://github.com/Meddyyyy0/my-first-devops-repo/actions/runs/42893965458
https://github.com/Meddyyyy0/my-first-devops-repo/actions/runs/42894403655
Второй запуск пропускает backup и pgloader по .migration_completed.

Использован официальный mattermost/mattermost-pgloader под Rosetta. Нативная PostgreSQL-схема создаётся Mattermost 9.5.0; перенос data-only генерируется официальным migration-assist v0.0.2. После восстановления индексов проверяются сообщения, затем запускается 12.0.1 и проверяется HTTP. Только после этого ставится флаг. Исходный MySQL volume и резервные копии сохранены, старый контейнер удалён.

Отличие от упрощённого шаблона include drop: перед повтором незавершённой миграции пересоздаётся целевая схема, затем выполняется data-only перенос. Это необходимо для совместимости служебных схем MySQL и PostgreSQL.

Пароли передаются через GitHub Secrets, не включены в исходники и архив. Журналы двух успешных запусков — verification/actions-run-1.log и actions-run-2.log.
